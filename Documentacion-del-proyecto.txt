1. OBJETIVO Y ALCANCE

El proyecto organiza la ayuda para personas afectadas por un terremoto en
Pereira, Risaralda. Permite registrar a una persona y su necesidad, recibir
ofertas de donación y llevar un control de los recursos recibidos y entregados.
El personal administrador también puede consultar las fichas, asignar cupos
de albergue y registrar el resultado del seguimiento.

El sitio tiene tres tipos de usuarios. La persona afectada registra sus datos
y solicita un recurso. La persona u organización donante ofrece un recurso y
deja un medio de contacto. El administrador inicia sesión para coordinar la
recepción de donaciones, las entregas, los albergues y los casos.

2. ARQUITECTURA Y TECNOLOGÍAS

Navegador (HTML, CSS y JavaScript) → API HTTP (Node.js y Express) → SQLite

- HTML estructura las páginas y los formularios. CSS y Bootstrap 5.2.3 dan
  estilo a la interfaz y la adaptan a pantallas de distintos tamaños. Bootstrap
  Icons se usa en el inicio y en el panel. Los archivos de Bootstrap se cargan
  desde jsDelivr y las fotos y escudos de la interfaz se sirven desde img/.
- JavaScript en el navegador usa Fetch para enviar solicitudes HTTP y
  actualizar los formularios, fichas y tablas.
- Node.js ejecuta el servidor. Express sirve las páginas y los recursos
  públicos y recibe las solicitudes en las rutas que empiezan por /api/.
- node:sqlite abre el archivo local y ejecuta las consultas parametrizadas.
- express-session mantiene la sesión. Multer recibe las fotos del formulario.
  El módulo node:crypto genera valores aleatorios y procesa las contraseñas.
- package.json define las dependencias y comandos de arranque. package-lock.json
  fija las versiones que se instalan con npm ci.

3. PÁGINAS HTML Y HOJA DE ESTILOS

index.html — Página pública de inicio. Presenta el objetivo del sistema,
  la misión y la visión, un carrusel y accesos al registro, las donaciones y
  la administración. Incluye canales de orientación sobre ayuda y albergues.

formulario.html — Formulario para personas afectadas. Solicita tipo y número
  de documento, nombres, apellidos y una necesidad con recurso, cantidad y
  prioridad. Admite datos adicionales de contacto y de la afectación, además
  de hasta tres imágenes opcionales con vista previa.

donaciones.html — Formulario público de ofertas. Solicita nombre, tipo de
  donante, teléfono o correo, recurso y cantidad. Permite añadir observaciones.
  Una oferta queda pendiente de confirmación hasta que llegue el aporte.

administrador.html — Pantalla de acceso y panel privado. Contiene el menú de
  consultas, los formularios para crear albergues y recibir donaciones y las
  plantillas de fichas y entregas. Desde las fichas se ven las fotos, se
  asigna un albergue y se registra el seguimiento o el aviso por WhatsApp.

css/styles.css — Estilos compartidos de navegación, botones, formularios,
  tarjetas, carrusel y panel. Incluye ajustes para pantallas pequeñas y
  estilos de foco para la navegación con teclado.

4. ARCHIVOS JAVASCRIPT

js/main.js — Punto de entrada del servidor. Configura Express y las sesiones. Sirve los HTML y los recursos públicos,
  valida las solicitudes, ejecuta las operaciones de base de datos y envía
  las respuestas. También ejecuta el comando para crear cuentas administradoras.

js/base-datos.js — Abre SQLite, aplica el esquema y ejecuta las transacciones.

js/recursos.js — Función compartida que lee el catálogo desde /api/recursos
  y llena los selectores con el nombre y la unidad de medida de cada recurso.

js/formulario.js — Obtiene la sesión y el catálogo. Aplica el límite de fecha
  de nacimiento, crea las vistas previas de las fotos y envía el registro con
  FormData. Muestra la confirmación o el error devuelto por el servidor.

js/donaciones.js — Carga la sesión y el catálogo, verifica que haya un
  teléfono o correo y envía la oferta en JSON. Si se guarda, limpia el formulario.

js/administrador.js — Controla el inicio y cierre de sesión y carga las fichas
  y tablas del panel. Envía las operaciones de albergues, donaciones, entregas
  y seguimiento. Prepara el enlace de WhatsApp y registra la confirmación
  manual. Si el servidor omite la lista de albergues, mantiene visibles las
  fichas y deshabilita temporalmente la asignación.

5. BASE DE DATOS

- basedatos/esquema.sql contiene todas las tablas y el catálogo inicial.
- basedatos/damnificados.sqlite es el archivo que se crea al arrancar. La ruta
  se configura con DB_FILE en .env.

Tablas principales

  damnificados — Identificación, nombres, contacto, afectación, fecha de
    registro y albergue opcional. El tipo y número de documento son únicos
    en conjunto.
  albergues — Nombre, dirección, teléfono y capacidad. Un albergue puede
    alojar a varias personas y cada ficha asignada ocupa un cupo.
  recursos — Catálogo con nombre, categoría y unidad de medida. La combinación
    del nombre y la unidad es única. Incluye agua, alimentos, kits de higiene,
    ropa, cobijas, colchonetas, cupos de alojamiento y otros recursos.
  necesidades — Vincula a la persona con el recurso que solicita. Guarda la
    cantidad, la prioridad, el estado, la fecha y las observaciones.
  donantes — Identifica a la persona u organización que ofrece o entrega ayuda
    y guarda sus medios de contacto cuando se informan.
  donaciones — Entradas de inventario. Guarda el recurso, cantidad, fecha de
    recepción, observaciones y, cuando corresponde, el donante.
  entregas — Salidas de inventario. Registra a quién se entregó el recurso,
    qué cantidad recibió, cuándo y qué administrador registró la entrega.

Tablas complementarias

  cuentas_administrador — Usuario único y hash de la contraseña.
  reportes_afectacion — Descripción ampliada de la afectación, cuando se aporta.
  fotos_damnificados — Fotos asociadas a una ficha. Guarda el tipo de imagen
    y el archivo como dato binario en una columna BLOB.
  seguimiento_damnificados — Estado de contacto o revisión y motivo, cuando
    corresponde. Puede quedar Pendiente, No se pudo contactar o No cumple.
  avisos_whatsapp — Fecha en la que un administrador confirmó manualmente
    el envío del aviso asociado a la ficha.
  ofertas_donacion — Vincula al donante con el recurso y la cantidad ofrecida.
  recepciones_donacion — Vincula una donación recibida con su oferta, cuando
    existe. Cada oferta admite una sola recepción y la solicitud tiene una
    clave única para reconocer reintentos.
  entregas_confirmadas — Vincula una entrega con la necesidad que atiende.
    Su clave de solicitud única permite reconocer reintentos.

Las claves primarias identifican las filas y las claves foráneas mantienen
las relaciones entre tablas. Las cantidades de recursos admiten hasta dos
decimales. Cuando una operación abarca varias escrituras,
el servidor usa una transacción para guardar todo junto o deshacer los cambios
si hay un error. SQLite serializa las escrituras mientras el servidor valida
cupos y existencias para controlar solicitudes simultáneas.

6. API UTILIZADA

El proyecto utiliza una API HTTP propia, implementada con Express en
js/main.js. El navegador la llama con Fetch. La dirección local es
http://127.0.0.1:3000 y las rutas empiezan por /api/. GET consulta datos y
POST registra acciones. Las respuestas usan JSON en general. El registro de
damnificados envía multipart/form-data para incluir las fotos y su consulta
devuelve la imagen en formato binario.

Rutas públicas y de acceso

  GET  /api/sesion
       Inicia o consulta la sesión. Devuelve el token CSRF, si hay un
       administrador autenticado, la fecha de Colombia y los límites de fotos.
  GET  /api/recursos
       Devuelve el catálogo de recursos con sus unidades.
  POST /api/damnificados
       Guarda una persona afectada, su necesidad y las fotos opcionales.
  POST /api/ofertas-donacion
       Registra el donante y la oferta.
  POST /api/administrador/ingresar
       Valida las credenciales, inicia la sesión de administrador y genera
       un nuevo token CSRF.

Rutas que requieren una sesión de administrador

  GET  /api/administrador/damnificados
       Devuelve las fichas, las referencias a sus fotos y los albergues.
  GET  /api/administrador/fotos/:id
       Devuelve la imagen identificada por :id.
  GET  /api/administrador/consultas/:seccion
       Devuelve columnas y filas de albergues, donaciones, ofertas, donantes,
       recursos, necesidades, entregas o colaboradores.
  POST /api/administrador/donaciones
       Registra una donación directa o confirma la recepción de una oferta.
  POST /api/administrador/albergues
       Crea un albergue con su dirección y capacidad.
  POST /api/administrador/damnificados/:id/albergue
       Asigna un cupo a la persona o libera su asignación.
  POST /api/administrador/necesidades/:id/entregas
       Registra una entrega asociada a la necesidad y actualiza su estado.
  POST /api/administrador/damnificados/:id/seguimiento
       Guarda el estado y el motivo del seguimiento.
  POST /api/administrador/damnificados/:id/confirmar-whatsapp
       Guarda la confirmación manual del aviso.
  POST /api/administrador/salir
       Cierra la sesión.

Todas las solicitudes POST llevan el token de sesión en X-CSRF-Token. Las
contraseñas administrativas se guardan como hashes scrypt con un valor
aleatorio (salt) por cuenta. Las fotos se limitan a tres archivos JPG, PNG o
WebP de hasta 3 MB cada uno. Solo se consultan con sesión de administrador.

La integración con WhatsApp usa un enlace https://wa.me/ con el número y el
mensaje sugerido. El administrador abre WhatsApp, envía el mensaje allí y
confirma la acción en el panel. El proyecto prescinde de la API de WhatsApp
Business, de envíos automáticos y de pasarelas de pago. Los sitios de la
Alcaldía y la Cruz Roja se ofrecen como enlaces informativos.

7. EJEMPLO DEL FLUJO DE AYUDA

1. Una persona afectada solicita cinco litros de agua en el formulario.
2. Un donante ofrece cinco litros. La oferta queda pendiente de recepción
   y el saldo del recurso permanece igual.
3. El administrador confirma los cinco litros recibidos. El inventario suma
   esa cantidad y la oferta queda vinculada a la recepción.
4. El administrador entrega dos litros desde Necesidades. El saldo del recurso
   baja a tres litros y la solicitud queda Parcial.
5. Al entregar los tres litros restantes, el saldo queda en cero y la
   solicitud pasa a Atendida. La ficha puede recibir un cupo de albergue si
   la persona también necesita alojamiento y hay capacidad disponible.

8. EJECUCIÓN LOCAL Y REVISIÓN

1. Con Node.js 22.13 o posterior, ejecuta npm.cmd ci en PowerShell.
2. Ejecuta npm.cmd start y abre http://127.0.0.1:3000/.
3. Para acceder al panel, sigue las instrucciones del README para crear una
   cuenta administradora.

El archivo .env contiene el puerto del sitio y la ruta de SQLite. Las
sesiones se mantienen en memoria durante la ejecución del servidor.
